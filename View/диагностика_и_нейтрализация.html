Метод Айронса (panic mode recovery) для восстановления после ошибок
Соболев Илья Олегович | АВТ-313 | Вариант 50

📌 Введение

При синтаксическом анализе программного кода неизбежно возникают ситуации, когда входная строка не соответствует грамматике. В таких случаях анализатор должен не только обнаружить ошибку, но и:

  • ✅ Сообщить пользователю о наличии ошибки
  • ✅ Указать точное местоположение ошибки (строка, позиция)
  • ✅ Предоставить понятное описание проблемы
  • ✅ Продолжить анализ для обнаружения остальных ошибок
  • ✅ Обеспечить возможность навигации по ошибкам

Для решения этих задач в разработанном анализаторе используется метод Айронса (panic mode recovery) — один из наиболее эффективных методов восстановления после синтаксических ошибок.

🎯 Метод Айронса (Panic Mode Recovery)

Суть метода: При обнаружении ошибки анализатор пропускает часть входной строки до тех пор, пока не найдёт специальный "синхронизирующий" символ (например, ';'), после чего анализ возобновляется. Это позволяет обнаружить все ошибки в программе за один проход.

// Основная идея метода Айронса: if (error_detected()) { report_error(); // сообщить об ошибке while (!is_sync_symbol(current_lexem)) { skip_lexem(); // пропускать лексемы } reset_to_safe_state(); // перейти в безопасное состояние }

Преимущества метода:

  • ✅ Простота реализации
  • ✅ Гарантированное завершение анализа
  • ✅ Обнаружение всех ошибок за один проход
  • ✅ Нет зацикливания при обработке ошибок
  • ✅ Низкие накладные расходы

🔄 Стратегии нейтрализации ошибок

В зависимости от типа ошибки и текущего состояния автомата применяется одна из четырёх стратегий:

📤 Стратегия 1: Пропуск лексемы

Недопустимый символ удаляется из потока, анализ продолжается со следующей лексемы.

Пример: float_form*at = ...
→ символ '*' пропускается
Применяется при: недопустимых символах

📥 Стратегия 2: Вставка лексемы

В поток вставляется ожидаемый символ, анализ продолжается без сдвига позиции.

Пример: result = "{:f}"format(...)
→ вставка '.' перед 'format'
Применяется при: пропущенных обязательных элементах

🔄 Стратегия 3: Замена лексемы

Ошибочный символ заменяется на ожидаемый, анализ продолжается.

Пример: "{:g}".format(...)
→ замена 'g' на 'f'
Применяется при: неверных форматных спецификаторах

⚡ Стратегия 4: Синхронизация

Поиск синхронизирующего символа (например, ';') для перехода в безопасное состояние.

Пример: x = "{:f}".format(5)
→ поиск ';', вставка ';'
Применяется при: серьёзных структурных ошибках

⚙️ Алгоритм диагностики ошибок

function DiagnoseError(state, lexem): ErrorInfo
{
    switch (state) {
        case Start:
            return "Ожидался идентификатор";
        
        case IdRem:
            return "Ожидался символ '='";
        
        case AfterEqual:
            return "Ожидалась открывающая кавычка '\"'";
        
        case Colon:
            if (lexem.lexemContaintment == "g")
                return "Неверный форматный спецификатор. Ожидался '{:f}'";
            return "Ожидалась буква 'f'";
        
        case CloseQuote:
            return "Ожидалась закрывающая кавычка и точка перед format";
        
        // ... остальные состояния
    }
    
    return "Синтаксическая ошибка";
}

🔬 Примеры обработки ошибок

Пример 1: Недопустимый символ

Входная строка: float_form*at = "{:f}".format(3.234e+4);
Позиция ошибки: символ '*' на позиции 10
Диагностика: "Недопустимый символ '*' в идентификаторе"
Действие: Пропуск символа, анализ продолжен
Результат: Ошибка зафиксирована, остальной код проанализирован

Пример 2: Неверный форматный спецификатор

Входная строка: result = "{:g}".format(-123.456);
Позиция ошибки: символ 'g' на позиции 12
Диагностика: "Неверный форматный спецификатор. Ожидался '{:f}'"
Действие: Замена 'g' на 'f', анализ продолжен
Результат: Ошибка зафиксирована, остальной код проанализирован

Пример 3: Отсутствует точка перед format

Входная строка: temp = "{:f}"format(0.001);
Позиция ошибки: сразу после закрывающей кавычки
Диагностика: "Ожидалась точка '.' перед методом format"
Действие: Вставка точки, анализ продолжен
Результат: Ошибка зафиксирована, остальной код проанализирован

Пример 4: Отсутствует ';' в конце

Входная строка: x = "{:f}".format(5)
Позиция ошибки: конец строки
Диагностика: "Отсутствует точка с запятой ';' в конце оператора"
Действие: Вставка ';', анализ завершён
Результат: Ошибка зафиксирована

🎯 Навигация по ошибкам

Разработанный анализатор предоставляет удобные средства для навигации по обнаруженным ошибкам:

  • 📊 Таблица ошибок — все ошибки отображаются в DataGridView с указанием строки, позиции и описания
  • 🖱️ Двойной щелчок — при двойном щелчке на строке с ошибкой курсор автоматически перемещается к месту ошибки
  • 🎨 Подсветка — ошибочные фрагменты кода подсвечиваются красным цветом в редакторе
  • 📋 Копирование — результаты анализа можно скопировать в буфер обмена

Пример отображения ошибок в интерфейсе:

📍 Ошибка [строка 1, позиция 12]: Неверный форматный спецификатор. Ожидался '{:f}'
result = "{:g}".format(-123.456);
^

✅ Вывод

Разработанная система диагностики и нейтрализации синтаксических ошибок на основе метода Айронса обеспечивает:

  • Точную диагностику — каждая ошибка сопровождается понятным описанием
  • Локализацию ошибки — указание строки и позиции в исходном коде
  • Восстановление после ошибок — анализ продолжается для обнаружения всех ошибок
  • Удобную навигацию — переход к месту ошибки по двойному щелчку
  • Визуальную обратную связь — подсветка ошибочных фрагментов

Данный подход успешно применён в разработанном синтаксическом анализаторе и показывает высокую эффективность при обработке различных типов ошибок.
